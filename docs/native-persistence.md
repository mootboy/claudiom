## Storage and bounds

Planned logs live at `$XDG_DATA_HOME/claudiom/v1/projects/<claude-project-key>/<session_id>/events.jsonl`, replacing implemented hashed-session storage. Derive the key from `basename(dirname(parent transcript_path))` in hooks, never recreate Claude's encoding. Strictly validate raw project/session components: bounded Unicode-scalar single names, no empty/`.`/`..`, separators, NUL or traversal; freeze exact specs in 004. Events and registry must agree on identity. No silent renaming/deletion.

Use absolute XDG_DATA_HOME or HOME/.local/share; reject empty/relative roots. MCP maps `CLAUDE_PROJECT_DIR` through the private registry; CLI uses cwd/`--project` and the recorded mapping, not encoded-path guesswork. URN recall finds the named session directory across projects without changing the URN, failing on ambiguous duplicate identities. Freeze bounded cross-project enumeration and CLI selector spelling in 004. Registry resolves scope only, never memory/coverage truth; retrieval needs no model credentials.

Create Claudiom-owned directories with mode 0700 and regular log files with mode 0600. Validate ownership against the effective UID and reject group/other permissions on Claudiom-owned entries. Reject symlinks in every existing path component, non-directory ancestors and non-regular log files. Do not chmod arbitrary existing directories. Shared XDG ancestors need not be private; Claudiom-owned entries must be. Open logs using no-follow flags and verify opened file identity against the checked entry. Do not claim protection against a malicious process running as the same UID or root.

Limits for v1: 1 MiB per framed event including LF, 16 MiB per session log, 256 memories per generation event, 16 KiB UTF-8 per memory text, 256 citations/supports per memory, 4 KiB UTF-8 per locator path, 256 bytes UTF-8 per stored identifier (valid Unicode scalar sequences); public memory URNs are bounded separately at 1550 ASCII characters, and 256 session logs per project scan. Exceeding a limit rejects the affected log or write; never return a silently truncated fold. Retrieval may skip rejected sessions with explicit warnings, as described below. Exceeding a project scan limit or separately frozen cross-project routing bound fails the invocation rather than silently truncating results. Rotation/compaction is not part of this slice. Check sizes before allocating whole-file reads, then enforce limits again on bytes actually read.

## Wire format

Each event is one UTF-8 JSON object followed by LF. No blank lines. Require strict UTF-8 and reject duplicate JSON keys. An unterminated final line is uncommitted even if it parses as JSON. An invalid LF-terminated line is corruption, not a repairable tail. Reject unknown versions, event kinds and fields. Validate with Clojure specs plus explicit cross-record invariants.

Every event has `version` (1), `event_id`, `session_id`, `recorded_at` (UTC RFC3339 timestamp), and `kind`. IDs are nonempty strings bounded as above; generated IDs should be UUIDs. Stored memory IDs are local to a session: different sessions may reuse the same local ID. Session IDs retain opaque source identity but the planned layout uses strictly validated raw values as single directory components; reject unsafe values rather than normalizing them.

### Public memory identity

`urn:claudiom` is a private, unregistered namespace used by this application; `claudiom` is not an IANA-registered URN namespace under RFC 8141. No public namespace registration or external resolver is claimed.

Retrieval exposes `id` as `urn:claudiom:<session>:<memory>` and adds `local_id` containing the stored ID. Each component is the original session/local ID encoded as UTF-8 percent escapes, with only ASCII letters, digits and `-._~` left literal; escapes use uppercase hex. No normalization of either original identifier is performed. Empty components, invalid UTF-8 escapes, noncanonical encodings, query/fragment suffixes and unsupported namespaces are rejected. The maximum is 1550 ASCII characters (13-character prefix, two components of at most 768 characters, and one separator). Example: session `session:one`, memory `memory/one` becomes `urn:claudiom:session%3Aone:memory%2Fone`.

On disk, memory definitions, supports and lifecycle references remain session-local. Public `supports` and `supersession.replacement_id` are qualified URNs, including in supporting observations. URN semantics are unchanged by the layout amendment; legacy-layout handling is a separate issue-004 contract, not permission to rewrite/delete logs.

### Generation

A `generation` event adds `coverage` and `memories` (an array, possibly empty). Coverage and all accepted memories form one commit. Invalid input rejects the whole event. The planned empty-result amendment stores a fixed-enum reason with coverage. Proposed wire field `empty_reason` is required for empty results and absent for nonempty results; initial proposed values are `routine`, `no_decisions`, `duplicate`, to freeze in 004. Current code lacks this field. MCP uses `record(handle, [], reason)`, never model-authored coverage.

Coverage has `lane` (`observation` or `reflection`), `input_id` and `from`/`to` nonnegative safe integers with `from < to`. Its identity is `(session_id, lane, input_id)`. Observation coverage additionally requires `prefix_sha256`, a lowercase 64-hex SHA-256 of source bytes `[0, to)`, computed by the producer from its read snapshot. It includes skipped oversized/malformed/unknown records and is committed atomically with the range and accepted memories, including successful empty commits. Reflection coverage is unchanged: stable observation-feed identity and feed positions, without `prefix_sha256`. The store validates structure, not source bytes.

Observation progress uses byte offsets at complete LF-terminated record boundaries. Coverage already includes `session_id`, so the stream key is `parent` or `agent:<agent_id>`, without session ID, path, inode or record content. Use `input_id = parent#<n>` or `agent:<agent_id>#<n>`; recover the highest committed `n` for that session/stream from the native fold, not a sidecar or volatile counter.

The source locator spec limits nonempty Unicode-scalar `agent_id` to 233 UTF-8 bytes. Together with 6 bytes for `agent:`, 1 for `#`, and at most 16 decimal digits for nonnegative safe-integer `n`, the input ID fits the native 256-byte bound (233 + 6 + 1 + 16 = 256). Boundary tests accept exactly 256 bytes with a 233-byte agent ID and `n = 9007199254740991`, and reject the 257-byte form with a 234-byte agent ID. Use canonical decimal (no leading zeros except `0`) and parse the final `#` suffix, preserving agent IDs containing `#`. Incarnation exhaustion fails visibly rather than wrapping. This locator bound does not change the general native stored-identifier limit.

Before resuming at the latest committed `to`, re-hash the current source prefix `[0, to)` in fixed chunks. A full digest match permits resume and preserves identity across path relocation or same-content inode replacement. A mismatch or size below `to` chooses `n = 1 + highest committed n` and replays from zero, without heuristic deduplication or inherited coverage. No prior committed incarnation means incarnation `n = 0` starting at byte zero; failed/precommit work does not consume an incarnation number. Missing/unreadable sources, cancellation and incomplete verification cannot justify unproven resume or silently mint a new incarnation.

Source selection/prefix verification has a 256 MiB per-stream snapshot cap: exceed it and report `stream_too_large`, without restart or progress. Hash-only scans are fixed-chunk operations outside the 32 MiB parsed/materialized-byte run budget. Stage 2 returns candidate ranges and prefix evidence; only successful native `record` commits advance authoritative coverage. The completed `/compact`, `--resume` and fork checks preserved prior bytes, satisfying D6 and freezing D1. `/clear` creates a new session/file with independent coverage. These scoped observations do not replace runtime prefix verification or authorize ancestry transfer; see issue 003. The store does not infer source identity/boundaries from Claude fields.

The first range starts at zero; subsequent ranges start at the prior committed `to`. Reject gaps, overlaps, regressions and a new event claiming previously covered work. Exact event replay is handled before coverage checks. Independent lanes and input IDs advance independently. Failed/cancelled work and expired/invalid/stale handles produce no event. Missing sources/no context are not successful empty commits.

Each memory has `id`, `kind`, `text`, and `source_time` (UTC RFC3339 or null when unavailable). Session and recording time are inherited from its generation event. An observation adds a nonempty `citations` array. A reflection adds a nonempty `supports` array of observation IDs, with no duplicates. An observation-lane commit accepts only observations; a reflection-lane commit accepts only reflections.

Each citation contains `citation_version` (currently 1, independently validated from the event version), `stream` (`parent` or `subagent`), `agent_id` (null for parent, nonempty for subagent), `path` (absolute source path), `source_id` (nonempty UUID/string or null), and `locator`. The locator has `input_id`, `start`, `end` and `sha256`: a nonempty half-open byte range and SHA-256 of its exact bytes. Native locators are required even when source IDs exist. Source IDs are metadata, not sufficient proof that a file still contains the cited bytes. The digest detects same-size in-place mutations that file identity/size checks alone miss. No transcript content is embedded in a citation. The path is a resolution hint, not immutable identity: Claude storage can move, and future source resolution may relocate it while verifying the native range/digest. Missing or unsupported citation versions are rejected; no implicit migration of earlier pre-release fixtures is performed. The [structural scan](claude-transcripts.md) observed millisecond-precision UTC timestamps compatible with native validation, but nonmonotonic source times. Stage-2 selection orders source records by byte offset, retaining timestamps as provenance; observed formats are not a universal Claude schema.

Reflection supports must already be committed observations in the same session, not reflections or unknown IDs. Dropped observations remain valid historical supports. The MCP server owns the opaque expiring handle table and revalidates membership, candidate ranges/prefixes and native invariants under the lock. Reflection supports must come from its table of committed observations. Misleading text with real citations remains an accepted traceable risk; structural membership is not truth. No producer drop/supersede tools.

### Lifecycle

Planned consolidation: a committed reflection implies `consolidated` status for exactly its validated supports, no new event kind. Remove these observations from active listings but retain definitions/citations for recall through the reflection. Empty reflections consolidate nothing; multiple reflections archive their support union, not every offered observation. Preserve drop/supersession/support-change links; freeze status precedence and stable reflection-feed mapping in 006, without renumbering after consolidation.

A `drop` event adds only `memory_id`. It hides that ID from active listing, retaining its first definition and provenance. Drop-before-definition creates a pending tombstone: a later definition remains dropped. Repeated drops with distinct event IDs are harmless; unknown dropped IDs are not recallable until defined.

A `supersede` event adds `memory_id`, `replacement_id` and `reason` (nonempty bounded text). Both definitions must already exist in the same session, have the same kind, and differ in ID. Reject cycles and a second different replacement for an already superseded ID. The old ID becomes inactive and recall exposes the link. New definitions arrive through generation, not inline lifecycle replacements. Repeated identical supersession is harmless.

Corrections never edit text in place. Corrected observations can invalidate reflection conclusions: expose affected reflections as `support_changed` and omit them from active listing until explicitly dropped or superseded. Preserve their historical supports for recall. Dropping a support alone does not assert its content was false and does not invalidate a reflection.

## Stage-2 source and attachment contract

Hook-shaped locator specs require absolute source paths without tilde/HOME expansion and tolerate extra envelope fields, including `scratchpad_dir`, `prompt_id` and `effort`; unrelated fields cannot authorize source discovery or control producer policy. Subagents use `agent_transcript_path`, not the parent path. Read explicitly supplied streams even with empty `agent_type`, but an absent subagent source is a normal no-op: no error, context, candidate/committed coverage or retry loop, including with prior coverage. Do not confuse this with a successful empty generation commit. Other healthy streams may progress. Stored-citation recall independently reports `missing` and preserves the stored memory.

Source selection orders by byte offset and retains per-record cwd, timestamps and explicit attribution. For non-attachment user records, omission gates precede inclusion: `isMeta: true` is omitted with a content-free marker; any present non-human/unknown/malformed origin is also omitted (including task notifications and peers). Retained `isCompactSummary: true` records carry `attribution: "compaction summary"` and `model_generated: true`, never a user/tool/SDK/delegating-parent label. Other retained records containing `tool_result` blocks are tool evidence, never user statements, regardless of stream, origin or SDK metadata. For remaining parent user text, human origin means user; absent origin means `user, origin unrecorded`, or `SDK caller` when `promptSource: sdk`, never a verified human statement. Subagent user text is attributed to the delegating parent agent, never the human, even with human-origin/SDK fields. These labels preserve model-generated compaction-summary provenance and cannot bypass omission gates. Omission advances candidate progress only; see 003 for the full rule and combination tests.

Selection applies an allowlist to top-level `attachment.type`:

- `queued_command`: use `prompt` as a user message only with both `commandMode == "prompt"` and `origin.kind == "human"`; do not require `humanTurn`. Absent/invalid guards, peer input and task notifications are excluded.
- `file` / `edited_text_file`: bounded filename-only markers using `displayPath`, else `filename`; absent names remain unavailable. Never include `content`/`snippet`, open the referenced file or claim its existence from the marker.
- All other/future attachment types: omit with content-free markers and candidate progress. `environment`, `session_context` and `credential_org` must never enter the generation context, including through raw-record fallback or copied metadata.

This record policy is distinct from image/attachment content-block omission. Exact original-record citations and prefix digests include processed/omitted bytes without asserting facts from omitted payloads. Stage 2 does not write coverage; the in-session record operation commits successful processing atomically. Tool-result sidecar expansion is outside issue 003; references alone authorize no file reads. The native writer validates structure, not this producer selection policy; see [003](issues/003-claude-source-reader-and-context-selection.md) for bounds and planned interface evidence.

## Folding and replay

Read the bounded authoritative log up front. Fold with pure processing, producing definitions, lifecycle state, event identities and coverage. Validate a proposed append against that fold, then perform writes at the end. Disposable checkpoints never override the log.

For the same event ID, equality means identical parsed event values (object key order is irrelevant, array order is significant). Exact replay is a no-op. Any changed value is a conflict. An existing memory ID may recur only with an identical first definition, including inherited session/recording time; otherwise reject. No later definition overwrites the first. Fold validation is all-or-nothing within each session: corruption yields no partial success or coverage result from that log. Reader scans may return other healthy sessions with warnings. Writers require a fully validated target-session log, not a store-wide log snapshot. URNs establish global identity from the session namespace without reading unrelated definitions.

## Append, acknowledgement and repair

Implemented writers require caller serialization. The planned amendment enforces a store-wide owner-only `O_EXCL` lock, bounded wait and age-based stale breaking (not PID-only inference). Hold it only for fold/validate/append/fsync and explicit repair, never model generation. Target corruption blocks its target, not unrelated log contents; check project directory names/cap under the lock. Shared-root/path failures remain fatal; readers never repair tails.

Freeze lock location, ownership token, expiry/wait limits and release/error behavior in 004. Age is not proof a paused owner is dead: test stale-break/old-owner-resume races before claiming exclusion. A roughly five-minute best-effort range lease reduces duplicate model work; contiguity and locked validation, not the lease, determine correctness. No detached worker.

Write the complete frame with a loop handling short writes, then fsync the file. For newly created entries, fsync containing directories so acknowledged storage survives restart. Acknowledge only after these operations succeed. In a write/fsync error, report an uncertain outcome and require recovery; never optimistically update coverage. Re-read the log on retry. A crash after a durable frame but before acknowledgement is resolved by event replay without another logical generation.

`append!` refuses every unrepaired tail, including on identical replay, without truncating or writing. A separate `repair!` operation / `repair --session <id>` command performs its own read/process/write cycle: validate the complete prefix, compute the last LF boundary, verify file identity/size, truncate the unterminated tail, then fsync. It never appends events or changes recovered coverage. Repair shares the store-wide serialization requirement. A retry also fsyncs an already-repaired existing file, because a previous truncate may have succeeded before fsync/acknowledgement failed. Repair of a missing log is a no-op and creates no storage. Never repair a malformed complete frame or skip corruption. A complete valid frame found after an uncertain write is authoritative during recovery; a missing/incomplete frame is not. Agent/model work may repeat after a precommit crash or session exit.

## CLI reader

- Planned cwd/`--project` scoping applies to list, scoped local recall and repair; freeze exact spelling in 004. URN recall resolves a session directory by name across projects, with bounded routing/ambiguity diagnostics. Current CLI uses the older hashed layout.
- `list [--session <id>]`: JSON array, active memories sorted by `(recorded_at, id)` ascending. Without a session filter, scan up to the session limit; do not create storage. A missing store is an empty list.
- `recall <urn> [--session <id>]` reads the encoded session's uniquely located log after bounded directory-name routing. An optional filter must match the URN's decoded session; otherwise exit 2. `recall <local-id> --session <id>` is a scoped shorthand (a `urn:claudiom:` prefix is interpreted as a URN); bare unscoped IDs are rejected rather than searched or guessed. Return a JSON object with the first stored definition, lifecycle status, correction links and provenance. For reflections, include supporting stored observations and their lifecycle statuses. Missing memory exits 1 after checking the target's committed definitions; only target-session corruption prevents establishing absence and causes exit 2 with `Memory unavailable; results incomplete.` Repair-needed warnings do not change a missing-memory exit code: unterminated tails are uncommitted and cannot contain stored definitions. Invalid arguments, unsafe store roots and store-wide scan-limit violations also exit 2.
- `repair --session <id>`: explicit write operation returning `{repaired, removed_bytes}` as JSON. Corrupt complete frames or unsafe storage exit 2 and are never repaired. This command is not retrieval.
- List/recall remain read-only, work without credentials/models/source transcripts, and preserve their JSON stdout shapes. On an incomplete tail, return the committed prefix and write `Repair needed for session <hash>; results incomplete.` to stderr; no implicit repair occurs.
- On an unreadable/corrupt session, skip its entire log and write `Corrupt session <hash>; results incomplete.` to stderr. Per-session unsafe entries, including symlinked or wrongly permissioned session directories/logs, are classified under this same `Corrupt session` warning and skipped, not treated as an invocation-wide exit 2 (also with `--session`). Unsafe store roots still fail the invocation with exit 2. The hash identifies the storage session even when its original ID cannot be recovered safely. Return healthy results (exit 0) while making incompleteness explicit. Unfiltered listing still scans healthy sessions and reports skipped sessions. Direct URN recall is unaffected by unrelated corrupt/torn logs and emits no warnings about sessions it never reads. Equal local IDs in different sessions are not conflicts; their URNs differ.
- Native consumers use `retrieve` to obtain `{result, warnings, incomplete}`. `incomplete` is true only for corrupt-session warnings; repair-needed warnings remain visible but do not make the committed-definition scan incomplete. CLI warnings contain only fixed text and validated session hashes, never private paths/transcript content. Root/scan errors are not swallowed as partial success.
- List returns `source_status: "not_checked"` without source I/O. Stored memory remains accessible regardless of source availability.
- Recall verifies each returned citation, including supporting observations, read-only through the source reader. Hash only the cited byte range, with no parsing, alternative-path discovery or covered-prefix scan. Report `source_status: "verified"` for a complete range with matching SHA-256, `"changed"` for different bytes or an out-of-bounds/truncated range, and `"missing"` for an absent source. Unsafe/unreadable sources (final-component symlink, wrong type, permission failure or inconsistent read) report `"unreadable"`; sources may have symlinked ancestors. Open read-only/no-follow, require a regular file and validate the opened identity. These source rules do not relax native-store symlink rejection. Growth or changed modification/change timestamps alone do not invalidate an intact cited range: require unchanged dev/ino identity and final size at least the cited end, then compare the range digest. Same-UID uncooperative rewrites remain outside the threat model; verification proves observed bytes, not permanent stability.
- Verification is bounded to the source per-line limit per range (default 1 MiB), **256 citation attempts and 16 MiB hashed bytes per recall**, shared across the memory and all supporting observations; failed attempts count. Bound descriptors and report `"verification_limited"` for unattempted/over-limit ranges rather than mislabeling them as checked outcomes. Read no bytes outside the cited range or opened snapshot size. `verified` establishes observed bytes only, not semantic truth, whole-stream integrity or permanent stability. Source statuses do not hide stored memories, change lifecycle/coverage, or convert an otherwise successful recall into a native-storage failure. Diagnostics remain content-free. List performs no verification and retains `not_checked`. Stage 2 returns statuses only. Cited-content expansion is not authorized merely by adding MCP read tools in revised stage 6; freeze any later expansion separately.
