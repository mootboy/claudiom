## Planned contract

### MCP read tools

Expose MCP `list({project, session_id})` and `recall({id, project, session_id})`, optional absolute project selector/session filter matching 004 CLI; recall ID may be URN or scoped local ID. Success is `{result, warnings, incomplete}` from native retrieval, missing recall fixed not_found error, invalid/unsafe/ambiguous/limited invocation fixed content-free error. Bound request to 16 KiB and response to **2 MiB**; larger complete result returns explicit limited error, never silently truncated data. Read-only: no models/state writes/repair/generation/credentials. Retain native healthy partial results, consolidated history and stage-2 citation statuses/supports. No prompt injection or cited-content expansion.

Writer allowlist stays exactly next_context/record even when read tools are available to other callers. No producer-facing drop/supersede. Permission rules are not a justification for arbitrary project/source discovery.

### Setup and permissions

`/claudiom:setup` documents installation, storage/project scope, hooks, manual remember, default Haiku, best-effort live-session completeness, threshold/backoff/lease behavior and possible Claude Code model spend. No separate API keys, SDK, direct provider adapter or cost-ceiling promise.

Document prompting/persisted allow where UI supports it; setup prints JSON permissions.allow containing exactly `mcp__plugin_claudiom_claudiom__next_context` and `mcp__plugin_claudiom_claudiom__record`, not wildcards or silent edits. Auto-mode spike did not test prompt persistence/fresh-config; those remain deferred, not claimed tested.

### Cache-contained distribution

Use separate plugin root with manifest, hooks, MCP config, memory-writer agent, remember/setup skills and committed runtime inside it. No references outside installed cache root, dev dependency installs or JVM/compiler runtime requirement. Resolve version-specific plugin root each invocation; XDG authoritative logs/state survive plugin updates independently of plugin-data uninstall semantics.

GPL-3.0-only CLI/plugin. Planned Claude Code floor **2.1.296**, Node >=22.19.0; older versions unsupported. Opt-in acceptance checks current supported installation/marketplace/cache, manifests/tarball/checksum/runtime-only consumption. No lifecycle pushes/unattended npm publication.

### Opt-in acceptance and release

User-run real sessions must demonstrate registration -> manual remember/eligible skill nudge -> restricted background writer -> observation/empty reason commit -> list/recall -> restart, then reflection consolidation and historical support recall. Include parent/subagent streams, writer self-exclusion, /clear's fresh explicit ID, compaction/resume, duplicate triggers/handles, ignored/classifier-blocked nudges and session exit with uncovered work. Distinguish main-turn survival from /exit cancellation; do not promise final flush.

Normal tests remain synthetic/private/fake MCP/delegation; no host credentials/transcripts/hooks or real agents. Real-use evidence records version/settings, structural outcomes and limitations without committing raw transcript/hook content. Model fidelity remains evaluated evidence, not semantic certification. No direct-provider probe or detached-worker lifetime acceptance under the superseded architecture.

After implementation/evidence acceptance, make the final version PR: package/lockfile/plugin manifest to 0.1.0, changelog date, clean regenerated runtime and packaged checks. Hosted CI and exact released-artifact/plugin smoke tests pass before Linus merges without squash. Tag only merged validated main with explicit approval; no agent PR merge, squash or lifecycle push.

## Planned acceptance evidence

- [ ] MCP read tools match native/CLI project and URN semantics, corruption/ambiguity/scan bounds, consolidated history and all five bounded citation statuses; read operations never call models/write state.
- [ ] Writer restriction remains two producer tools plus observed built-in handback; added read tools do not broaden its allowlist. Setup allow syntax names exactly the two tools.
- [ ] Setup documents defaults, project mapping, best-effort lifetime/model billing and permission limitations honestly; no unverified manual-mode persistence/fresh-config claims or wildcard permission edits.
- [ ] Synthetic interface/process tests cover runtime-only package and cache-contained manifests/agent/skills/hooks/MCP paths with no compiler/JVM/credentials/dev dependency/runtime external-root requirement.
- [ ] Scoped opt-in installed real use covers observation/empty commit/restart, registry/nudge/backoff/duplicate work, source attribution, reflection consolidation and historical supports; uncovered exit-cancelled progress remains visible.
- [ ] Node/Claude floor, Linux support and current-version spike limitations are recorded; deferred classifier/provenance/model configuration tests are not presented as acceptance evidence.
- [ ] Tests, clean CI, check:dist, hosted CI and exact tarball/plugin/checksum/license smoke tests pass; normal tests remain fake/synthetic/private.
- [ ] User accepts functionality and final release PR, merges without squash and separately approves a tag on merged validated main; version changes/publication do not happen as a side effect of this plan.
