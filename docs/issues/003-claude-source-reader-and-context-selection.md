## Explicit locators and source safety

- Use Clojure specs for the relevant hook-shaped projection: `session_id`, `transcript_path`, `cwd`, and subagent `agent_id`, `agent_type`, `agent_transcript_path`. Tolerate unrelated envelope fields and optional fields absent from particular events; never treat them as reader instructions.
- Parent reads use `transcript_path`; subagent reads use `agent_transcript_path`, never the parent path on `SubagentStop`. Read every explicitly supplied subagent stream, including empty `agent_type`. Automatic eligibility belongs to stage 4.
- Require bounded valid identifiers and explicit absolute source paths/cwd. Use the user's manual hook capture to establish whether real `transcript_path` / `agent_transcript_path` values can begin with `~/`; if observed, define expansion against absolute `HOME` in the locator spec before freezing it. No implicit shell expansion, transcript discovery, hardcoded Claude root, or paths derived from prose/agent IDs. `cwd` is provenance, not permission to scan a project.
- Open with `O_RDONLY | O_NOFOLLOW`, rejecting a symlink only in the final component. Allow symlinked ancestors. Require a regular file and validate the opened identity. Claude-owned entries do not need Claudiom's private storage modes; never chmod them. Native-store path safety remains stricter and unchanged.
- Take initial size/identity from the descriptor; read no bytes past that size, even after appends. Consume only LF-terminated records. A partial tail never becomes candidate progress. Preserve exact byte offsets and original line terminators in hashes, including CRLF; characterize BOM handling without normalizing citation bytes.
- Reads happen up front, selection is pure, and sources are never written, renamed, repaired or locked. Validate mutation evidence around reads and retry/reject observed inconsistencies; append growth alone is acceptable. An initial size is not an atomic snapshot against in-place rewrites or a malicious same-UID writer.
- Source failures have fixed content-free statuses and cannot mutate native memories/coverage or hide stored memories.

## Bounds and omission

Defaults:

| Bound | Default |
| --- | --- |
| Complete source line, including LF | 1 MiB |
| Source stream snapshot | 256 MiB |
| Source bytes parsed/materialized per run, shared across supplied streams | 32 MiB |
| Estimated tokens | UTF-8 bytes / 4 |

The token calculation is an estimate, not a tokenizer accuracy or spend guarantee. Selection accepts explicit byte/token budgets; stage 3 chooses production thresholds and provider limits. Bound selected output and open descriptors as well as input allocation.

Hash-only reads use fixed-size chunks and do not consume the parsed-byte budget. The per-stream cap bounds prefix verification and scanning for LF; a stream over the cap reports `stream_too_large`, without parsing it, silently restarting, or advancing candidate coverage. This cap applies before allocation and is rechecked against actual reads.

For each complete line:

- **Oversized:** never parse JSON, including with a streaming parser, or materialize the whole line. Stream through its LF and full SHA-256; emit a content-free marker with exact `[start, end)`, digest and `reason: oversized`. Advance candidate progress past that line. All accompanying text is intentionally lost. The scan may exceed the parsed-byte budget because it is hash-only; no cross-run continuation state is needed.
- **Malformed normal-sized:** emit the same range/digest marker with `reason: malformed` and advance. Invalid UTF-8/JSON or ambiguous malformed records must not stall a stream indefinitely.
- **Unknown record type:** omit with a marker and advance. Unknown fields/block shapes are not blindly included in context.
- **Normal-sized image/attachment blocks:** omit binary/base64 payloads with image/attachment omission markers while retaining surrounding text and tool results. Do not discard the whole record merely because it contains an attachment.
- **Incomplete tail:** no completed marker/digest and no progress across it.

Normal-sized records count against the parsed-byte budget even if parsing leads to omission. Stop before a record that cannot fit that budget; never jump over unprocessed relevant records. Hashing omitted complete lines establishes byte processing, not facts from their content. Stage 3 carries skipped-line progress into successful atomic coverage commits; failure/cancellation still commits nothing.

## Incarnation and resume integrity

Amend unreleased native v1 observation coverage with required `prefix_sha256`: SHA-256 of source bytes `[0, to)`, computed from the read snapshot and committed atomically with coverage and memories, including successful empty commits. Reflection coverage is unchanged. Update specs and synthetic fixtures when implementation is authorized; there is no migration or compatibility reader for older pre-release observation coverage. No XDG-state sidecar is introduced.

Coverage is already scoped by `(session_id, lane, input_id)`, so the stream key contains no session ID: `parent` for the parent or `agent:<agent_id>` for a subagent. Use **`input_id = parent#<n>` or `agent:<agent_id>#<n>`**. Paths, inodes and record content are not identity inputs; the fold is the authority for committed incarnation numbers within that session/stream.

The locator spec bounds `agent_id` to **234 UTF-8 bytes**, nonempty valid Unicode scalar text. Reserve 5 ASCII bytes for `agent:`, 1 for `#`, and up to 16 decimal digits for a nonnegative safe-integer `n`, keeping the full ID within 256 bytes. Encode `n` in canonical decimal without leading zeros (except `0`); parse the final `#` suffix so an agent ID containing `#` remains unambiguous. Incarnation exhaustion fails visibly, never wraps or aliases an ID.

Resume algorithm:

1. Find the latest committed incarnation and its observation `to`/`prefix_sha256` in the native fold. With no committed incarnation, select incarnation `n = 0` and start at byte zero; an empty source yields no nonempty candidate range.
2. Re-hash current source bytes `[0, to)` in fixed chunks within the stream cap. Only a full digest match permits resuming at `to`. This detects middle-prefix rewrites even when first/last records are unchanged.
3. On mismatch or current size below `to`, use `n = 1 + highest committed n` for that stream and replay from zero. Repeated rewrites with identical first records get new incarnations once prior coverage is committed. No heuristic deduplication or ancestry/coverage transfer.
4. Relocated paths and same-content inode replacement retain the incarnation when the covered prefix matches. Missing/unreadable sources, cancellation, incomplete verification and `stream_too_large` do not authorize a restart or unproven resume.
5. Return a contiguous candidate range starting at resumed `to` (or zero for a new incarnation), together with SHA-256 of `[0, candidate to)`. The digest includes omitted bytes. Candidate assignment is not durable; retries derive identities from the recovered fold, not volatile counters. Failed/precommit work cannot consume an incarnation number or advance coverage.

Prefix evidence is bound to the native event, so restart and uncertain acknowledgement use the recovered committed frame. Reader selection never writes coverage. The narrowly scoped native schema/spec/fixture amendment is an approved stage-2 dependency, not permission to implement before this issue is ready.

**Evidence gate:** any observed rewrite rather than append blocks freezing this resume/incarnation contract until the behavior has been examined. The approved direction is not a claim that uncharacterized Claude rewrite semantics are already supported.

## Citation verification during recall

`recall` verifies returned citations, including all supporting observations, through bounded read-only range hashing. Use the stored path hint; no alternative-path discovery, parsing, covered-prefix scans, model calls or source-content return. `list` does no source I/O and retains `not_checked`.

| `source_status` | Meaning |
| --- | --- |
| `verified` | Complete safely readable range with matching SHA-256 |
| `changed` | Different bytes or out-of-bounds/truncated range |
| `missing` | Absent source |
| `unreadable` | Unsafe/unreadable source, including final symlink, wrong type, permission failure or inconsistent read |
| `verification_limited` | Verification omitted because a range or shared recall limit prevents it |

Allow symlinked ancestors, but never follow a final symlink to classify its target. `verified` proves only bytes observed in this read, not semantic truth, permanent source stability or whole-stream integrity. Never read outside the cited range or opened snapshot size.

A range may be at most the per-line bound (default 1 MiB). One recall shares limits of **256 citation attempts and 16 MiB hashed bytes** across the memory and supporting observations. Count failed attempts too; bound descriptors and never label unattempted/over-limit ranges as checked outcomes. Source statuses preserve stored-memory output, lifecycle and native error/exit semantics; source failure alone does not fail an otherwise successful recall.
