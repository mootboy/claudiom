# Native persistence contract and reader

- Status: in-progress
- Category: enhancement
- Parent: [001 — Initial 0.1.0](001-initial-release.md)
- Milestone: stage 1 of the [release plan](../plan-0.1.0.md)

## Goal

Deliver the smallest native private-file store and independent `list` / `recall <id>` CLI. Synthetic generation commits must survive restart with memories and coverage intact, including successful empty results. No producer or model is needed for this milestone.

Current behavior is bootstrap-only: no persistence, listing or recall exists.

## Contract decisions

The initial contract is recorded in [Native persistence contract v1](../native-persistence.md). Review these decisions before implementing the writer:

- Versioned event schema, stable event/memory identity, and first-definition, identical-replay and conflicting-replay semantics.
- Observation provenance: session, recording time, parent/subagent stream identity, source UUID where present, and a native locator for UUID-less records.
- Citation shape: build citations only from hook-provided identity — `session_id`, stream (`parent`, or the subagent's `agent_id` from `SubagentStop`), record `uuid` where present, and a line/byte offset — with the absolute transcript path stored only as a resolution hint, since `~/.claude` can move and paths encode the cwd. Version the citation format independently of the event schema (e.g. `{:v 1 ...}`) so stage 2 can add locator kinds after characterizing compaction/resume/fork rewrites without migrating stored records.
- Reflection support references to committed observations; validation of missing/invalid supports and preservation of dropped supports.
- Explicit append-only correction/supersession and tombstone semantics, including drop-before-definition behavior. Never silently replace a committed definition.
- Coverage identity and bounded progress representation, keyed per source stream (parent and each subagent transcript progress independently), including independently tracked observation/reflection progress. One generation commit contains accepted memories and associated coverage; an empty result is valid.
- Exact XDG layout, absolute-root validation, hashed session path components, owner-only permissions and non-symlink safety.
- Append framing, durable acknowledgement, partial-tail detection/repair, malformed-record handling and numerical read/event/item limits. Repair is a separate process with its own read/process/write cycle. The writer refuses to append after an unrepaired incomplete tail; retrieval stays read-only, ignores the incomplete tail and reports that repair is needed.
- CLI session selection, output/error behavior, listing order and recall representation for active, dropped, missing and conflicting records.

These remain decision gates, not permission to assume undocumented Claude transcript fields. Review against [architecture](../architecture.md), [memory semantics](../memory-model.md), and [Claude integration guidance](../claude-integration.md).

## Desired behavior and interfaces

- A native writer accepts validated synthetic generation commits and lifecycle events. Invalid input does not change authoritative state.
- A pure fold derives memories, lifecycle state and coverage from the authoritative log. Checkpoints are not required for correctness.
- `list` reads active stored memories without credentials, source transcripts or generation.
- `recall <id>` exposes stored content and provenance, including supporting observations for reflections and historical dropped records. Unavailable source files are reported honestly without hiding the stored memory.
- Read state up front, process purely, and write at the end. Keep related behavior local; prefer Clojure specs for validation.

## Acceptance criteria

- [ ] The native format, storage paths, safety rules, limits and CLI contract are documented with synthetic examples.
- [ ] A commit containing observations and coverage survives process restart and is directly usable through `list` and `recall`.
- [ ] A successful empty commit advances durable coverage without creating memory; replay after restart does not create a second logical generation.
- [ ] Memory and coverage commit together. Validation failure, failed append, cancellation or incomplete commit never advances recovered coverage.
- [ ] Identical replay, conflicting replay, corrections, tombstones and drop-before-definition follow the documented contract without silently overwriting first definitions.
- [ ] Parent/subagent and UUID-less citations round-trip; recall preserves attribution, session/stream provenance and recording time. Citations carry an independent format version.
- [ ] Coverage for a parent stream and its subagent streams advances and recovers independently.
- [ ] Reflection support validation rejects unsupported references; recall can explain a reflection through preserved dropped observations.
- [ ] Crash/restart fixtures cover incomplete tails, the separate repair process, writer refusal before repair, read-only retrieval over an unrepaired tail, crash after durable append but before acknowledgement, and coverage reconstruction without checkpoints.
- [ ] Malformed input and oversized records/reads fail according to bounded, documented behavior without exposing private content in diagnostics.
- [ ] Filesystem interface tests verify private permissions, invalid roots and symlink rejection without touching host state.
- [ ] Packaged CLI tests demonstrate list/recall after restart without credentials or model calls, including missing memory/source behavior.
- [ ] Tests focus on interfaces with parameterized cases; property-based tests cover fold/replay invariants where applicable. Fixtures are synthetic and state is private temporary storage.
- [ ] `npm test` passes; clean release output is regenerated in `dist/claudiom.js`. Completion records test/evidence links, not just code.

## Open decision before stage 4

Open decision — user approval required before stage 4: one corrupt complete session log blocks commits store-wide, because writers scan every session strictly and repair refuses malformed complete frames. This could prevent background-worker progress in unrelated sessions. Decide whether to retain explicit human intervention, add an operator-controlled quarantine command that renames the corrupt native log/session aside, or check global ID conflicts only against readable logs. Any choice must specify uniqueness, retained history/coverage and bounded visible worker failure. No policy change or quarantine implementation is authorized in stage 1.
